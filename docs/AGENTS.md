# Documentation Rules

Follow the root AGENTS.md and the Moziserve agent workflow.

- Write all new and edited prose without emojis or em dashes, including examples, headings, alternative text, and commit messages.
- Keep verified observations, proposed design decisions, and unknowns explicitly separate.
- Attribute source facts with the exact URL, capture date, and evidence file when available.
- Record unsuccessful access attempts as failures in this environment. Do not infer that the public website is offline.
- Preserve original source captures unchanged. Write normalized copy separately and apply the project writing rules to published copy.
- Update source-audit.md when new evidence arrives and delivery-plan.md when a milestone actually passes.
- Never mark unrun checks as passing or turn placeholders into business claims.
- Retain existing website colours. Document exact source values and distinguish palette evidence from proposed component styling. Keep the aesthetics review pending until the user has inspected it.
